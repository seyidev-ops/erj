## The Five-Finger Model

Every diagnostic surface, product page and piece of routing copy on this site runs on five parts, tested in this order. Capacity is first.

| # | Part | The line used on the site |
|---|------|---------------------------|
| 01 | **Capacity** | You can't be hired for work you can't yet do. |
| 02 | **Supply** | You can't apply for a job you never saw. |
| 03 | **Representation** | If your CV can't be read, you were never really in the running. |
| 04 | **Aim** | Applying everywhere isn't the same as applying where you'd get hired. |
| 05 | **Conversion** | Interviews don't pay you. A signed offer does. |

The teaching metaphor is a hand — thumb Capacity through to little finger Conversion. The finger assignment is a design convention only and does not rank the parts.

Diagnose the earliest evidenced constraint. Ties resolve upstream. A person may have more than one gap; record the others rather than forcing a single answer.

**Any surface still describing a four-part model is out of date and must be corrected, not left in place.**

## Current first-contact journey

Cold or uncertain visitors should not be asked to choose among ERJ products first. The current acquisition path is:

1. **Your Starting Line** — `starthere.html` is the default cold-traffic destination for social posts, ads, QR codes, generic learn-more links and first-contact campaigns.
2. **Find the problem** — the free five-part diagnostic at `/diagnose/` identifies the earliest failing point and returns a branded PDF report.
3. **Free first action** — the visitor receives a useful next move before any paid recommendation.
4. **AUDIT on WhatsApp** — optional human review when the visitor wants ERJ to inspect the evidence.
5. **Correct ERJ door** — only after diagnosis should the smallest suitable paid route be introduced.
6. **Register / payment** — `register.html` supports a decision already made. It is not the default first-contact page.

The homepage remains the institutional ERJ ecosystem. Its first screen nevertheless prioritises the free diagnostic, with the wider site available as the secondary path.

## Deployment

This package contains the current ERJ Website and is intended to be uploaded to the GitHub Pages repository root.

1. Extract the package.
2. Upload/commit the extracted website files to the repository root.
3. Keep `CNAME` in the root so the custom domain remains attached.
4. Bump the service-worker cache version and the `?v=` query on shared modules when those files change.
5. Generate the service-worker precache list from the real file list — one missing entry aborts the entire precache.
6. Do not add internal campaign notes, historical patch notes, test reports or old versioned deployment files to the public website repository.
7. Keep this `README.md` current when the website structure or commercial architecture changes.

There is no required build step for ordinary deployment; the repository contains the current static website files.

## Single source of truth

Every commercial fact on this site — prices, cohort dates, product names, the
diagnostic model, the official phone line, published credits — lives in one
place and is enforced by one script.

**`erj-config.js` → `canon`** holds the facts.
**`erj-facts.js`** can render them into marked-up spots at runtime (not currently loaded by any page).
**`validate-facts.py`** fails the build when any file disagrees.

### Pages state facts as real text

Every page carries its prices, dates and names as ordinary HTML text, so they
are visible to search engines and to readers without JavaScript. **Changing
canon does not change a page by itself.** To change a fact: edit canon, update
every page that states it, then run the gate below. Anything missed fails.

`erj-facts.js` is an optional renderer for spots marked with
`data-erj="price.foundation"`, `data-erj="cohort.closesDisplay"`,
`data-erj-href="pay.foundation"` and similar keys. No page loads it or uses
those attributes today. A page that adopts it must load `erj-config.js` first,
then `erj-facts.js`, and call `window.ERJFacts.paint(node)` for markup built
after load.

### The gate

```bash
python3 validate-facts.py          # exits 1 on failure — run before every deploy
python3 validate-facts.py --warn   # report only
```

Eight checks: retired terms, the official line, money figures outside canon,
the cohort in play, an expired window still advertised as open, the model
enumerated without Capacity, README drift, and payment links in canon that
appear on no page.

- Retiring a term is a one-line addition to `canon.retired`. It is enforced
  from that moment.
- Portal surfaces keep cohort history and are exempt from the cohort check.
- `blog.html` and `testimonials.html` are dated archives: drift there is
  reported as a warning rather than blocking a deploy.
- A line carrying `canon-ok` is exempt from every check. Use it rarely, and
  only where the exception is genuinely correct.

### Why it exists

This README previously described a four-part model and a retired cohort for
weeks after both had changed, because the same facts were written into a
dozen files and only some of them were updated. A config nobody checks is
just another document that goes stale. The gate is what makes the single
source of truth permanent.

Change a price in `erj-config.js`, update the pages that state it, and run the
gate. Anything that did not follow is caught before it ships.

`README.md` is the business and structure reference for this website package. `CLAUDE.md` holds the working rules for code changes. No other Markdown documents belong here.
